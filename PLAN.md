## 1. Target stack

### Why this stack

- **Next.js replaces Astro *and* Express.** File-based routing gives the multi-page structure; `app/api/*/route.ts` replaces every Express endpoint; `next/image` + Supabase Storage gives automatic WebP/AVIF + responsive `srcset` (was a "fast-follow" item — now free); `app/sitemap.ts` / `app/robots.ts` replace the hand-rolled dynamic sitemap; the Metadata API replaces manual `<head>` and JSON-LD wiring. One framework, one deploy.
- **Vercel** — global CDN for static/ISR pages, a preview URL per push (makes the phased rollout safe), zero server to babysit.
- **Supabase** — one service for the three things the current Express app does badly: durable content storage (no more JSON-on-disk wiped by deploys), file uploads (Storage bucket, not local `uploads/`), and real admin auth (Supabase Auth, not a shared password). RLS enforces public-read / admin-write at the database.
- **Fonts** via `next/font/google` — self-hosted at build time, no runtime request to Google (removes the GDPR question about Google Fonts logging IPs), better LCP.
- **Mail** via **Resend** (Vercel-native, good deliverability, generous free tier). `nodemailer` + SMTP is the fallback if a mailbox is preferred over an API.

### What gets deleted

`server.js`, `admin.html` / `admin.css` / `admin.js`, `script.js`, `styles.css`, `index.html`, `render.yaml`, `site.webmanifest` (regenerated by Next), the `express` / `multer` / `nodemailer` / `compression` / `express-rate-limit` deps. `data/content.json` + `data/gallery.json` + `uploads/*` are kept only as the **seed for a one-time migration** into Supabase, then removed.

## 5. Phase 2 — Supabase

### 5.1 Schema (`supabase/migrations/0001_init.sql`)

```sql
create table content_blocks (
  key         text primary key,             -- 'site' | 'bygg' | 'software'
  data        jsonb not null,
  updated_at  timestamptz not null default now()
);

create table services (
  slug        text primary key,
  division    text not null default 'bygg',
  title       text not null,
  short_desc  text,
  hero_lead   text,
  icon        text,                          -- svg path string
  price_from  text,
  duration    text,
  areas       text[] default '{}',
  faq         jsonb default '[]',            -- [{q,a}]
  sort        int  default 0,
  published   boolean default true,
  updated_at  timestamptz not null default now()
);                                           -- long body = content/tjanster/{slug}.mdx

create table projects (
  slug        text primary key,
  title       text not null,
  service_slug text references services(slug),
  location    text,
  year        int,
  summary     text,
  scope       text[] default '{}',
  duration    text,
  testimonial jsonb,                          -- {quote, author}
  cover_path  text,                           -- path in 'gallery' bucket
  before_path text,
  after_path  text,
  gallery     jsonb default '[]',             -- [{path, alt}]
  featured    boolean default false,
  sort        int default 0,
  published   boolean default true,
  created_at  timestamptz not null default now()
);

create table cases (                          -- software case studies (body = content/case/{slug}.mdx)
  slug        text primary key,
  title       text not null,
  client      text,
  summary     text,
  metrics     jsonb default '[]',             -- [{label, value}]
  featured    boolean default false,
  published   boolean default true,
  created_at  timestamptz not null default now()
);

create table gallery_images (                 -- standalone gallery not tied to a project
  id          uuid primary key default gen_random_uuid(),
  path        text not null,                  -- path in 'gallery' bucket
  alt         text,
  division    text default 'bygg',
  sort        int default 0,
  created_at  timestamptz not null default now()
);

create table leads (
  id          uuid primary key default gen_random_uuid(),
  created_at  timestamptz not null default now(),
  division    text not null,                  -- 'bygg' | '01'
  kind        text not null,                  -- 'offert' | 'kontakt' | 'brief'
  name        text, email text, phone text,
  service     text, budget text, timeline text,
  message     text,
  source      jsonb,                          -- {utm_source, utm_medium, utm_campaign, referrer, page}
  status      text not null default 'new',    -- new|contacted|won|lost
  note        text
);

create table admins ( user_id uuid primary key references auth.users(id) on delete cascade );

create or replace function is_admin() returns boolean language sql stable as
  $$ select exists(select 1 from admins where user_id = auth.uid()) $$;
```

### 5.2 RLS (`0002_rls.sql`)

- `content_blocks`, `services`, `projects`, `cases`, `gallery_images`: `enable row level security`; policy `select` `to anon, authenticated using (true)` (for `projects`/`services`/`cases` add `using (published or is_admin())`); policy `all` `to authenticated using (is_admin()) with check (is_admin())`.
- `leads`: `enable row level security`; **no `anon` policy at all**. Policy `select`/`update` `to authenticated using (is_admin())`. Inserts happen only in route handlers using the **service-role** client (bypasses RLS) — the public anon key cannot read or write leads.
- `admins`: `select` `to authenticated using (is_admin())`; no insert/update/delete policy (managed in the Supabase dashboard).

### 5.3 Storage

- Bucket `gallery`, **public read**. Policies: `insert`/`update`/`delete` `to authenticated using (is_admin())`.
- Upload path convention: `projects/{slug}/{uuid}.{ext}`, `gallery/{uuid}.{ext}`.
- `next/image` serves them via the public URL + Supabase host in `remotePatterns` → automatic AVIF/WebP + `srcset`.

### 5.4 Auth

- Supabase Auth, **email/password, public signup disabled**. Create 1–2 users in the dashboard; insert their `user_id` into `admins`.
- `middleware.ts` + `@supabase/ssr`: on `/admin/*` and admin API routes, load the session, 302 to `/admin/login` if absent; in each admin page/route also assert `is_admin()` server-side.
- `/admin/login/page.tsx` — Supabase `signInWithPassword`, nothing fancy.

### 5.5 Migration (`supabase/seed.ts`, run once)

Reads `data/content.json` → `content_blocks` rows (`site`, `bygg`) + `services` rows (9, seeded from `services[]`); reads `data/gallery.json` + uploads each file from `uploads/` to the `gallery` bucket → `gallery_images` rows. Idempotent (upsert on primary key). After it runs and is verified, delete `data/*.json`, `uploads/`, and the old root files.

### 5.6 Admin CRUD

`/admin` sections, all Server Components with Server Actions writing via the authenticated Supabase client:

- **Företag** — edit `content_blocks.site` (NAP, hours, socials, legal, `site_url`). One form, JSON-backed fields.
- **Bygg** — edit `content_blocks.bygg` (hero, stats, trust points, process, FAQ, featured project slugs) + reorder/toggle `services`.
- **01** — edit `content_blocks.software`.
- **Projekt** — CRUD `projects`, upload cover/before/after/gallery to Storage.
- **Galleri** — CRUD `gallery_images`.
- **Leads** — table (date, division badge, name, phone, service, status), expand for full message, status dropdown, CSV export, `tel:` / `mailto:` quick actions.

Every save calls `revalidatePath()` (or hits `/api/revalidate`) so published pages update immediately while staying static/ISR-cached otherwise.

**Deliverable:** existing content + photos live in Supabase; owner can edit everything except long-form MDX bodies.

## 7. Phase 4 — Business layer

### 7.1 Lead capture (highest business value)

- `app/api/offert/route.ts`, `contact/route.ts`, `brief/route.ts`: validate with zod → **insert into `leads` via the service-role client first** (a mail failure must never lose a lead — the current Express code loses it entirely) → then `mail.notify()` (internal, `replyTo` = lead email) → then `mail.autoreply()` (to the submitter, division-branded "Tack — vi hör av oss inom 24 timmar"), both mail calls guarded so failure returns success to the user but logs.
- `source` captured from `utm_*` query params + `referer` + submitting path.
- Rate-limit: `@upstash/ratelimit` (or a simple in-memory limiter per IP) since Express's `express-rate-limit` is gone.

### 7.2 Analytics + consent (launch-blocking together)

- `components/Analytics.tsx` — `@next/third-parties/google` `<GoogleAnalytics gaId={NEXT_PUBLIC_GA_ID}>`, loaded only after consent.

- Events: `generate_lead` (params `division`, `form`), `phone_click`, `whatsapp_click`, `service_view`.
- Optional alongside: Vercel Web Analytics + Speed Insights (cookieless, no banner needed).
- Google Search Console: verify via DNS TXT (survives host changes); submit `/sitemap.xml`.

### 7.3 Trust & conversion UI

- Badge row component (`F-skatt`, `Ansvarsförsäkring`, `ID06`, `5 års garanti`) on `/`, `/om-oss`, `/offert`.
- `components/StickyCall.tsx` — mobile-only, `Ring` + `WhatsApp`, bygg only, hides when a form is on screen.
- `components/BeforeAfter.tsx` — range-input clip slider on `/projekt/[slug]`.

## 16. Risks & mitigations

| Risk | Mitigation |
|---|---|
| **Trust dilution from a mixed audience** — a homeowner sees "software division" and reads generalist; a software buyer sees a construction site and doubts the engineering. | Keep the lanes physically separate: `/` never sells software beyond one restrained header link; `/01` never sells renovation beyond the back link. Different tone, colour, proof. Frame the link as credibility ("vi bygger både hus och system"), never a bundle. Watch bygg-home bounce after launch. |
| **New domain = zero authority.** No rankings to inherit. | Treat as a fresh launch: front-load GBP, NAP citations (hitta.se, eniro.se, allabolag.se), GSC indexing requests. Keep the 301 map for any external links to the old hash URLs. If the old domain was ever indexed, 301 it wholesale. |
| **Serverless has no filesystem** — the old `multer`→disk and JSON-on-disk model cannot be ported. | That's the reason for Supabase. Storage bucket for files, Postgres for content + leads, RLS for access. Migration script seeds from the current `data/*.json` + `uploads/*`. |
| **`SUPABASE_SERVICE_ROLE_KEY` leak = full DB access.** | Server-only env var; never imported into a client component; `lib/supabase/admin.ts` has `import 'server-only'` at the top. Anon key + RLS is all the browser ever gets. `leads` has no anon policy so even a misconfig can't expose it. |
| **Scope creep** — ROT calc, before/after, blog, city pages all competing with launch. | Everything in §14 is explicitly post-launch. The only Phase 4 blockers are lead persistence, auto-reply, consent, and the policy page. If a phase slips, `/01` ships as "kommer snart". |
| **Rebrand + framework change + colour change at once** makes bugs unattributable. | Phase 0 (facts only) lands first. Phase 1 builds the shell with hardcoded props before Phase 2 wires data. Preview deploys per push isolate regressions. |
| **Empty / stock gallery** undermines the whole trust argument on a trade site. | Hard launch blocker. If photos aren't ready, launch `/projekt` with 2–3 written case studies and no photo grid rather than stock. |
| **Vercel Hobby vs Pro** — commercial use on the free tier violates Vercel's terms. | Budget Pro ($20/mo) from day one; still less than Render paid + disk, with a CDN and preview deploys included. |
